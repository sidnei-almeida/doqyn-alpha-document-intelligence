2. NOVO SCHEMA / CAMPOS
--------------------------------------------------------------------------------
Coleção: audit_logs (append-only, tenant-scoped — padrão existente preservado).

Campos principais gravados:
  _id, tenantId, documentId, versionId, actor (snapshot expandido), action, description,
  area, result, severity, metadata (sanitizada), requestId, occurredAt, createdAt.

Metadata enriquecida pelo trackingService:
  status: success | failed | denied | pending
  actionGroup: lifecycle | preview | download | access | storage | governance | explorer | user | system
  security: { ipHash, userAgentHash, userAgentSummary, sessionIdHash, permissionResult, ... }
  target, before, after, changes (quando aplicável)

Listagem (DocumentTrackingListItem):
  + status, actionGroup, result, sessionHash

Detalhe (DocumentTrackingDetail):
  + security (sanitizado na leitura)

3. CAMADA CENTRAL
--------------------------------------------------------------------------------
server/services/tracking/
  trackingService.ts      — emitTrackingEvent, emitAccessDeniedEvent, emitClientTrackingEvent
  trackingSecurity.ts     — hash IP/UA/sessão, buildSecuritySnapshot
  trackingTypes.ts        — taxonomia, allowlist cliente, resolveActionGroup/Status
  trackingSummaryService.ts — agregações Mongo para dashboard

Políticas:
  - Falha de tracking NÃO derruba fluxo principal (catch silencioso em emitTrackingEvent).
  - sanitizeAuditMetadata bloqueia token, cookie, objectKey, presignedUrl, OCR, etc.
  - IP e User-Agent apenas como hash (+ resumo seguro de UA).
