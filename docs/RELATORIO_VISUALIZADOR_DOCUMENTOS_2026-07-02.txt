1. CONTEXTO E EVOLUÇÃO DO TRABALHO
================================================================================

PROBLEMA INICIAL
----------------
A seção Documentos existia de forma parcial: listagem sem integração completa,
ações de visualizar/baixar/detalhes não funcionais, preview em drawer lateral
com iframe do navegador (toolbar cinza nativa, fora do tema DOQYN).

OBJETIVO FINAL
--------------
Entregar um Document Viewer extensível, seguro e alinhado ao tema DOQYN, capaz
de suportar PDFs de vários tamanhos/proporções, imagens no futuro, e previews
protegidos para usuários sem permissão de download.

PRINCÍPIOS MANTIDOS EM TODAS AS FASES
--------------------------------------
- Preview sempre via backend autenticado (sem URL R2, sem presigned URL)
- objectKey nunca exposto ao frontend
- Isolamento por tenant respeitado
- Tracking auditável (preview_viewed, downloaded)
- Watermark DOQYN no preview PDF gerado pelo backend

6. FASE 5 — ARQUITETURA DINÂMICA COM MANIFEST DE PREVIEW
================================================================================

PRINCÍPIO CENTRAL
-----------------
O frontend não adivinha tipo/dimensões apenas pela extensão. O backend retorna
um manifest JSON orientando viewerType, dimensões por página e URLs internas.

ENDPOINT PRINCIPAL
------------------
GET /api/documents/:documentId/versions/:versionId/preview/manifest

Resposta inclui:
  - documentId, versionId, fileName, mimeType
  - viewerType: pdf_pages | image | unsupported | deep_zoom_image (futuro)
  - pageCount, pages[] com width, height, rotation, aspectRatio
  - previewUrl e thumbnailUrl (URLs internas /api/..., nunca R2)
  - image{} com resoluções small/medium/large (quando aplicável)
  - permissions: canPreview, canDownload, canUpdate, canViewTracking
  - status: ready | processing | failed

ENDPOINTS DE ASSETS
-------------------
GET .../preview/pages/:page        → PNG da página (Ghostscript, 144 dpi)
GET .../preview/thumbnails/:page   → miniatura (72 dpi)
GET .../preview/image              → preview de imagem (quando existir)
GET .../preview/image?size=medium  → resolução específica

EXTRAÇÃO DE DIMENSÕES
---------------------
- pdf-lib extrai width/height/rotation por página do PDF watermarkado
- Suporta A4 retrato, paisagem, carta, legal e páginas mistas no mesmo doc
- Cache futuro: MongoPreviewManifest em MongoDocumentVersion.previewManifest

VIEWER REGISTRY (FRONTEND)
--------------------------
viewerRegistry.ts escolhe componente automaticamente:

  pdf_pages  → PdfPagesViewer
  image      → ImageViewer
  outros     → UnsupportedViewer

COMPONENTES
-----------
PdfPagesViewer:
  - Carrega páginas como imagens autenticadas (usePreviewAsset)
  - Escala por width/height do manifest (não assume A4)
  - fit width: escala = largura_disponível / page.width
  - fit page: min(largura, altura) respeitando proporção
  - Lazy load acima de 20 páginas
  - Aviso para documentos grandes

ImageViewer:
  - Fit screen, fit width, zoom, pan/drag, rotação 90°
  - Carrega resolução medium por padrão
  - Placeholder funcional; pipeline de imagem no backend ainda parcial

UnsupportedViewer:
  - Mensagem amigável + opção de download se canDownload

HOOKS
-----
- usePreviewManifest: react-query para manifest
- usePreviewAsset: fetch autenticado + revokeObjectURL no unmount

BLOQUEIO DE BLOB PDF PARA USUÁRIOS SEM DOWNLOAD
------------------------------------------------
readDocumentPreviewFile() agora rejeita entrega do PDF completo quando
canDownload=false, retornando código PREVIEW_BLOB_RESTRICTED (403).

Usuários com apenas canPreview devem usar:
  manifest → páginas/imagens renderizadas server-side

Renderização interna (Ghostscript) usa allowBlobWithoutDownload:true apenas
no servidor — o blob nunca chega ao browser nesses casos.

----------------

9. PERMISSÕES E SEPARAÇÃO PREVIEW VS DOWNLOAD
================================================================================

| Permissão        | Efeito no viewer                                      |
|------------------|-------------------------------------------------------|
| canPreview       | Necessário para abrir modal e carregar manifest       |
| canDownload      | Exibe botão baixar; permite blob PDF legado (antigo)  |
| canUpdate        | Exibe botão atualizar (→ /upload?documentId=...)    |
| canViewTracking  | Exibe botão tracking                                  |
| canEditMetadata  | Mapeado para canUpdate no manifest                    |

TRACKING
--------
- document.preview_viewed: ao servir manifest com trackView=true
- document.downloaded: ao baixar original
- Zoom/paginação NÃO geram eventos adicionais (evita spam)

================================================================================
10. PERFORMANCE E LAZY LOADING
================================================================================

PDF (PdfPagesViewer):
  - pageCount <= 20: carrega/renderiza todas as páginas visíveis
  - pageCount > 20: lazy load (página atual ± 1)
  - Mensagem: "Algumas páginas serão carregadas sob demanda"

IMAGEM (ImageViewer):
  - Resolução medium por padrão
  - Preparado para trocar para large em zoom alto (futuro)

SERVIDOR:
  - Páginas renderizadas on-demand via Ghostscript
  - Dimensões extraídas uma vez por request de manifest (cache Mongo futuro)
