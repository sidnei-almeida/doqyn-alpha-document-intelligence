2. DIAGNÓSTICO POR ETAPA
================================================================================

confirmAnalysis era chamado?
  SIM — status "done" na fila só é setado em UploadQueueProvider.confirmItem
  após confirmAnalysis retornar documentId (único dispatch type:'done').

Documento salvo no Mongo?
  SIM — consulta direta em documents_company_dev mostrou documentos com:
  classId cat_juridico, status active, processingStatus processed,
  tenantType business, tenantId company_dev, ownerUserId preenchido.

listDocuments retornava o documento?
  SIM no backend (teste direto com admin/owner retornou 2 docs na raiz e
  com categoryId=cat_juridico).

Frontend recebia e escondia?
  NÃO — causa principal nesta rodada: cache/refetch insuficiente após confirm.
  invalidateQueries sem refetchQueries ativo + staleTime 30s faziam a Biblioteca
  manter lista vazia mesmo com documento persistido.

Diferença "análise concluída" vs "documento confirmado":
  - analyze:success → análise/staging prontos; NÃO salva na Biblioteca
  - status review → aguarda ReviewDrawer ou auto-confirm countdown
  - confirm:success (201) → documento no Mongo; único momento de "salvo"
  - Headline "Uploads concluídos" era enganosa (pendingCount=0 incluía só
    done/error, mas o rótulo sugeria sucesso final mesmo sem documentId)

Causa raiz 1ª rodada (mantida):
  buildDocumentOwnershipFilter excluía docs legados sem tenantId — corrigido.

Causa raiz 2ª rodada (esta correção):
  Frontend não refetchava listDocuments de forma confiável após confirmAnalysis.

Causa raiz 3ª rodada (definitiva — reproduzida no browser):
  api.documents.list passava filtros com valores `undefined` para URLSearchParams,
  que os serializa como strings literais "undefined":
    GET /api/documents?search=undefined&categoryId=undefined&...
  O backend interpretava search="undefined" e retornava lista VAZIA.
  Tracking funcionava porque monta query params de forma segura (sem undefined).

Evidência:
  - Mongo: 3 docs em documents_company_dev (cat_juridico, active, processed)
  - listDocuments backend direto: 3 itens
  - curl ?excludeArchived=true: 3 itens
  - curl ?search=undefined&...: 0 itens  ← bug
  - Após fix serializeQueryParams: Biblioteca mostra 3 recentes + Jurídico 3 arquivos
