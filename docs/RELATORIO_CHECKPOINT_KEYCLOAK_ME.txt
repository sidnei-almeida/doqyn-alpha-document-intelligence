7. ROLES — KEYCLOAK vs MONGODB
================================================================================

Keycloak (realm roles — autenticação/token):
  company_admin, user
  Responsável por: identidade, login, emissão de JWT, roles no token

MongoDB (tenant_members — autorização contextual):
  tenantRoles: ["company_admin", "user"]
  accessGroupIds: []  (permanecem no MongoDB, não no Keycloak)
  status: active      (membership no cliente)

Separação de responsabilidades:
  Keycloak → quem é o usuário e quais roles globais o token carrega
  MongoDB  → a qual tenant pertence, se está ativo/pending/blocked, grupos de acesso

COMO TESTAR
================================================================================

Túnel SSH (Keycloak na VPS):
  ssh -L 8080:127.0.0.1:8080 doqyn@187.77.59.114

Variáveis locais (.env):
  VITE_AUTH_PROVIDER=keycloak
  VITE_KEYCLOAK_URL=http://127.0.0.1:8080
  VITE_KEYCLOAK_REALM=doqyn
  VITE_KEYCLOAK_CLIENT_ID=doqyn-web
  KEYCLOAK_BASE_URL=http://127.0.0.1:8080
  KEYCLOAK_REALM=doqyn
  KEYCLOAK_ADMIN_CLIENT_ID=doqyn-admin-api
  KEYCLOAK_ADMIN_CLIENT_SECRET=<seu secret>
  KEYCLOAK_FRONTEND_CLIENT_ID=doqyn-web

Seed / verificação MongoDB:
  npm run db:setup
  npm run db:keycloak-checkpoint

Subir API + frontend:
  npm run dev

Login:
  1. Abrir http://localhost:5173
  2. Login Keycloak com sidnei
  3. Obter access token (DevTools → rede ou keycloak.token)

Testar /api/me manualmente:
  curl -s http://localhost:3001/api/me \
    -H "Authorization: Bearer <access_token>" | jq

Ou definir token e rodar checkpoint HTTP:
  KEYCLOAK_TEST_ACCESS_TOKEN=<token> npm run db:keycloak-checkpoint
