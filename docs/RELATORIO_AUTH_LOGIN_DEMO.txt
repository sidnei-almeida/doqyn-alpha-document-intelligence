1. CAUSA RAIZ
--------------------------------------------------------------------------------

O login falhava principalmente porque o banco Postgres do auth-service estava
VAZIO (0 users, 0 tenants, 0 memberships).

Sintoma: POST /auth/login → 401 INVALID_CREDENTIALS para admin.global@doqyn.dev.

Fatores contribuintes:
- Após `npx prisma migrate reset` ou volume Postgres novo, o seed demo não
  havia sido executado.
- `npm test` no auth-service apaga users/tenants/memberships no beforeEach quando
  TEST_DATABASE_URL não está separado — pode esvaziar o banco de dev se
  compartilhar DATABASE_URL (risco documentado em audit:auth-health).
- Problema secundário já observado: processo `dev:api` desatualizado sem rotas
  de profile → /api/profile/me retornava 404 até reiniciar o servidor.
- Frontend: redirect pós-login apontava para /upload em vez de /biblioteca.
- useProfileMe sem guardas podia disparar queries antes da sessão ou propagar
  erro de avatar/profile de forma agressiva.

NÃO era:
- mock/fallback inseguro no frontend
- senha demo alterada (permanece DevDoqyn@123)
- tenant company_dev ausente no seed (existe após dev:seed:demo)
- membership pending para admin global (fica active)
