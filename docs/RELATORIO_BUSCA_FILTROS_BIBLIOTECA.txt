================================================================================
2. BUSCA (TopBar)
================================================================================

Implementação: GlobalSearchCommand.tsx + useDebouncedValue (400ms)

Comportamento:
- Digitar na Biblioteca atualiza ?q= após debounce (sem reload).
- Enter navega/confirma /biblioteca?q=termo (replace=false no histórico).
- ESC limpa busca ou remove foco.
- Botão X limpa imediatamente (evita re-aplicar termo antigo via debounce).
- Loading discreto via useIsFetching(['documents']) na WorkspaceTopBar.
- Fora da Biblioteca, Enter redireciona para /biblioteca?q=.

Placeholder atualizado: "Buscar documentos por nome, categoria ou proprietário..."
(pessoas/pastas como entidades separadas permanecem pendentes — API só documentos).

================================================================================
3. CAMPOS PESQUISADOS (backend)
================================================================================

server/utils/documentListQuery.ts — buildDocumentSearchOrClause:
- title, currentFileName, displayName, originalFileName
- recommendedFileName, aiSuggestedFileName, finalFileName
- className (categoria), documentType
- ownerName, createdBy.displayName, createdBy.email
- metadata.tags

Regex sanitizado (escapeRegexLiteral, máx. 120 chars) — sem text index Mongo ainda.

Pendentes / limitações:
- Metadados extraídos além de tags (campos dinâmicos de extração).
- Descrição dedicada (se existir no schema futuro).
- Busca por pessoas como entidade (só match em owner/createdBy nos documentos).
- Filtro "Erro" — processingStatus no schema não inclui error; não exposto na UI.

================================================================================
4. ESCOPO: RAIZ VS PASTA
================================================================================

URL:
- /biblioteca?q=contrato
- /biblioteca?space={categoryId}&q=nda
- /biblioteca?space=juridico&q=nda&scope=all  → busca em toda a biblioteca

buildLibraryDocumentFilters:
- Raiz: categoryId = state.space (se em pasta) ou vazio.
- Pasta + scope≠all: categoryId = state.space.
- Pasta + scope=all: categoryId omitido (busca global).

SearchScopeHint: "Buscando em {pasta}" + link "Buscar em toda a Biblioteca".

================================================================================
5. FILTROS FUNCIONAIS
================================================================================

A. Status (FilterMenu / chips)
   - Todos, Ativo, Processado, Em análise, Aguardando revisão, Revisão necessária, Arquivado
   - Mapeamento UI → API (libraryFilterUtils.mapStatusToApiFilters):
     * processed → status=active + processingStatus=processed
     * analyzing → processingStatus=pending
     * pending_review / review_required → processingStatus=requires_review
     * archived → status=archived
     * active → status=active

B. Categoria/Pasta
   - Via ?space= (navegação existente). Filtro de categoria separado não duplicado
     quando já dentro da pasta.

C. Tipo (TypeFilterMenu): pdf | image | other — backend buildDocumentTypeClause

D. Período (PeriodFilterMenu): today | 7d | 30d | month — filtra updatedAt (from/to ISO)

E. Proprietário (OwnerFilterMenu): me | others — backend owner=me|others + ownerUserId

Pendentes:
- Filtro "Erro" (sem campo backend confiável).
- Período personalizado (from/to na URL) — não implementado nesta fase.
- Lista dinâmica de categorias no filtro (usa pastas via ?space=).

================================================================================
6. ORDENAÇÃO
================================================================================

URL: sort + direction
Opções: Mais recentes/antigos, Nome A–Z/Z–A, Categoria, Status, Proprietário

Backend: resolveDocumentListSort — campos permitidos:
updatedAt, currentFileName (name), status, ownerUserId (owner), className (category)

Fallback client-side: sortDocuments.ts (coleções virtuais e pós-filtro local).

================================================================================
7. URL COMO FONTE DE ESTADO
================================================================================

useLibraryRouteState persiste:
q, space, status, type, period, owner, scope, sort, direction, view

clearFilters() remove q, status, type, period, owner, scope (mantém sort/view/space).

Exemplo:
/biblioteca?space=juridico&q=nda&status=active&type=pdf&sort=updatedAt&direction=desc&view=grid
