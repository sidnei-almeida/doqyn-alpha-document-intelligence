<objective>
Harden the public edge in `deploy/nginx/default.conf` by (1) adding the five security response headers at the single nginx chokepoint that fronts both doqyn-api and auth-api (requirement AUTHSEC-03 / audit S-2) and (2) adding per-IP rate limiting to the token-guessable public/guest routes (requirement SEC-01 / audit S-3).

Purpose: The app today serves zero security headers and has zero rate limiting on its public routes. Guest share/sign links render externally-linked content with no clickjacking or CSP protection, and share tokens / signature-verification codes can be brute-forced with no throttle at all — a surface that grows as more live share links exist. Both fixes belong in nginx (one chokepoint, no app-code change), independent of the disabled-by-default, fail-open tenant-quota mechanism in `server/tenancy/tenantQuotas.ts`, which serves fair-use, not abuse-prevention.

Output: An updated nginx config that emits all five headers on every response (with a CSP scoped so guest share/sign flows keep working) and returns 429 from nginx once a per-IP burst limit is exceeded on the four public route prefixes.
</objective>

<!-- Deployment facts the executor needs — no exploration required. -->
- default.conf is copied to /etc/nginx/conf.d/default.conf (Dockerfile.nginx line 32). The stock nginx.conf `include`s conf.d/*.conf INSIDE the http{} block, so `limit_req_zone` (which is only valid in http context) belongs at the TOP of default.conf, outside the existing `server {}` block, alongside the existing top-level `resolver` and `upstream` directives.
- The file currently has ONE catch-all `location /api/ { ... proxy_pass http://doqyn_api; }`. The four public prefixes to rate-limit (`/api/share/`, `/api/external-shares/`, `/api/sign/`, `/api/verify/signature/`) are more-specific prefixes; nginx routes to the longest-matching prefix, so each needs its own `location` block that REPEATS the same proxy directives as `/api/` PLUS a `limit_req`.
- Guest-facing frontend routes and their SPA entry components (for CSP scoping): external-share portal (`src/features/external-share/ExternalSharePortalPage`), signature portal + verification (`src/features/signature/SignaturePortalPage`, `SignatureVerificationPage`), plus `src/features/guest-portal/` and `src/features/sharing/`. PDF preview uses `pdfjs-dist` (web worker + blob: URLs + WASM).
</interfaces>

<constraints>
- Headers MUST be set with the `always` parameter so they appear on error AND 429/503 rate-limited responses, not just 2xx.
- nginx `add_header` does NOT merge across contexts: if any `location` declares its own `add_header`, it drops all inherited ones. Set the five headers ONCE at `server {}` scope and do NOT add per-location `add_header` (so every location inherits them). The new rate-limited location blocks must NOT declare their own add_header.
- CSP MUST NOT break the guest share/sign pages, which render same-origin PDF previews (pdfjs: worker-src/blob:, WASM), signature images (img-src data:/blob:), and fetch content from /api (connect-src 'self'). Do NOT ship a bare `default-src 'self'` that blocks these.
- Rate limiting is per-IP (`$binary_remote_addr`), lives entirely in nginx, and is independent of `tenantQuotas.ts`. Do NOT touch application code.
- HSTS is only meaningful over HTTPS; nginx here listens on :80 (TLS terminated upstream at the VPS/Hostinger layer). Still emit the header (success criterion requires it on `curl -I`), but do NOT add a `listen 443`/cert block — TLS termination is out of scope for this phase.
- Rate thresholds MUST be env-tunable or clearly-commented constants (operator will tune to real traffic). A too-aggressive threshold breaking legitimate guest bursts is an explicit risk — pick a threshold that absorbs a normal multi-asset guest page load (PDF + signature image + a few polls) via `burst=` before throttling.
</constraints>
</context>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → nginx | Unauthenticated clients hit guest share/sign/verify routes with guessable tokens |
| nginx → doqyn-api / auth-api | nginx is the single origin chokepoint fronting both services |
| guest browser → rendered share/sign page | Externally-linked/same-origin content (PDF previews, signature images) rendered under CSP |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Information Disclosure / Elevation | /api/share, /api/external-shares, /api/sign, /api/verify/signature | mitigate | Per-IP `limit_req` (zone=public_edge, 429 on overflow) throttles brute-force token/verification-code enumeration at the edge, independent of the fail-open tenant quota |
| T-01-06 | Tampering (clickjacking / XSS containment) | all responses | mitigate | `X-Frame-Options SAMEORIGIN` + `frame-ancestors 'self'` block clickjacking of guest pages; CSP contains any future XSS; `X-Content-Type-Options nosniff` blocks MIME confusion |
| T-01-07 | Denial of Service (self-inflicted) | legitimate guest burst traffic | mitigate | `burst=` sized to absorb a normal multi-asset guest page load before throttling, plus a tunable rate constant with operator guidance — prevents the rate limit itself from breaking legitimate flows |
