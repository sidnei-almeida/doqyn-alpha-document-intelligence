<facts>
- Providers compose in `src/app/providers.tsx` (QueryClient → Theme → Confirm → ErrorBoundary → Auth). Entry: `src/main.tsx` → `src/app/App.tsx`.
- `index.html` currently hardcodes `<html lang="pt-BR">`; a runtime effect must override it to track the active locale.
- Existing theme sync pattern: an inline script in `index.html` sets `documentElement.dataset.theme`; mirror that intent for `lang` but from React (subscribe to i18next `languageChanged`).
- Shell string sources to migrate:
  - `src/lib/constants.ts` — NAV_ITEMS_LIBRARY_VIEWS, NAV_ITEMS_ADMIN, NAV_ITEMS_PRIMARY carry hardcoded `label` strings.
  - `src/components/layout/Sidebar.tsx` — "Biblioteca" inline nav item, "Administração" section label, collapse/expand aria-labels.
  - `src/components/layout/SidebarNavItem.tsx` — renders `item.label` (and passes it to SidebarTooltip).
  - `src/components/layout/SidebarSection.tsx` — renders `label` prop.
  - `src/components/layout/WorkspaceTopBar.tsx` — aria-labels "Ajuda", "Configurações".
  - `src/components/layout/SidebarStoragePanel.tsx` — "Armazenamento", "Gerenciar".
- Migration approach for nav constants: replace hardcoded `label` with a translation key field (e.g. `labelKey: 'library'`) and resolve with `t(item.labelKey)` in the rendering component, OR keep `label` and translate at render via a key map. Choose one and apply consistently; the value shown must come from the `nav` namespace, not a literal.
- Keys already authored in plan 01-02 (`nav`/`common`) — reuse them; do not duplicate. If a needed key is genuinely missing, add it to ALL three catalogs.
</facts>
